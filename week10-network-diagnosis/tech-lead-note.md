The server had no network errors when this test was conducted. The pre-change capture showed that ens18 was functioning with the DHCP assigned IP address 10.10.50.103/24, a default route via 10.10.50.1 was established, and that sshd was listening for IPv4 and IPv6 traffic on port 22. All pings to 8.8.8.8 and google.com replied with four successful responses, thus confirming proper operation of routing and DNS. Following the assignment, I ran sudo ip route add default via 10.10.50.1, which created an additional default route entry without a metric value next to the existing DHCP-learned entry with a metric of 100, and a repeat run of the same command displayed RTNETLINK answers: File exists. Ping tests and traceroutes demonstrated connectivity through 10.10.50.1 as the initial hop. The post-fix capture was collected using the same commands used to collect the pre-change capture; the post-fix capture records the final status of the system. Any changes made with ip route add are temporary and will be lost during a reboot. Persistent routes on Ubuntu normally belong in netplan. The final step is to remove the manually added route with ip route delete, or reboot to remove it, so the routing table matches the documentation.
