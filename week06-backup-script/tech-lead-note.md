The /etc directory is backed up using the script backup_etc.sh, which creates a timestamped compressed tar file. The purpose of this backup is to have a way to restore the system's configuration should some kind of incident occur. When backup_etc.sh runs, it saves each backup to /var/backups/etc. This includes a name for the backup based on the date and time when it ran. So, no matter how many times you may run backup_etc.sh, it will never overwrite the previous backup.

Each major step in backup_etc.sh is logged to /var/log/backup_etc.log through the use of a custom logging function called log(), which uses tee -a to print to the terminal and append to /var/log/backup_etc.log, and adds a timestamp to each message. Error checking looks at the return code of tar. In other words, if tar returns anything but zero, the script prints an ERROR message and then terminates with a status code of 1; otherwise, the last message written to the log file will indicate that a valid archive has been created and include the location and size of the archive.

backup_etc.sh is version controlled through Git on the same Linux server where it is running. Two commits each have a message describing what changed. These provide an audit trail showing exactly what has happened since the first time the script was checked in.
