I used the system log to review the SSH logs on the 1601 virtual machine using systemd's journalctl. I searched using journalctl -u ssh and reviewed /var/log/auth.log. The search indicated that there were 0 failed login attempts as well as no lines in the multi-pattern search of Failed password OR Invalid user. Since there were zero failed login attempts, no source IP could rank higher than another. I ran the following command: grep "Failed password" /var/log/auth.log | awk '{print $11}' | sort | uniq -c | sort -rn | head -10; and received nothing back. All Accepted publickey logins were logged from 10.10.65.11, which is my internal workstation. I verified that this VM logs high precision timestamped values, so by count the source IP on a Failed password line would be field #9 as opposed to field #11. I suggest you check to see if password auth has been disabled by running sshd -T. If it has, then there will never be a password prompt for an attacker to attempt a guess against. And therefore no escalation is required at this time.
