Technical Lead Note

The health_report.sh file captures a health snapshot of the server as one report. First, it records the name of the host and the date. Next, there are labeled sections for disk with df -h, inode usage with df -i, memory with free -h, load with uptime and the number of CPU cores with nproc. Then, five samples each of CPU and I/O activity are recorded using vmstat 1 5. Lastly, the listening services are reported by ss -tlnp. Each time this script is run, it generates a new report that is placed in ~/reports. Each report generated by the script will be named based upon the name of the hostname, the date, and the time. Cron places both the results from running the script and any errors into ~/reports/health_cron.log. The last crontab contains a PATH line and one command line. That line reads 0 6 * * * and executes the script at 06:00 am server local time every day. Server local time is set to use UTC. Using ls -la ~/reports and then tail -80 on the most recently generated report will show that a report was generated and display its contents. Reviewing the evidence indicates that the server is healthy. Disk usage for the root filesystem is 36%, and inode usage is 22%. There are 3.3 GiB out of 3.8 GiB of memory available. The average load is 0.01 over 4 processor cores. The vmstat displayed 100% idle CPU utilization with no I/O wait. Port 22 and port 80 were reported as listening on all IP addresses, while port 53 was reported as listening on loopback only.
