server-setup.sh sets up the web service on a brand-new Ubuntu Server. In the first pass through it updates the list of available packages with apt update, installs nginx with apt install -y so nothing will prompt for user input and prevent automated runs, enables and starts nginx with systemctl enable --now, so that after each reboot nginx is automatically started again. Then at the end, it verifies success/failure by printing out either SUCCESS or ERROR based upon the exit code of systemctl is-active --quiet, and returns a value of 1 if there is a failure.

I tested how this script behaves when you are starting with a completely clean slate. So I purged nginx and then ran apt autoremove which also removed nginx-common. When I ran systemctl status nginx, it stated that the unit could not be found, therefore, I had confirmed the server was back to a completely clean state. I ran the script as root using sudo bash and it installed both packages from scratch and printed SUCCESS.

It appears that the script's own check indicates that nginx is active. Independently, I also checked the same thing from my command-line terminal: the output of systemctl is-active indicated active, and the output of systemctl is-enabled indicated enabled; these outputs indicate that nginx is currently running, and has been configured to continue running after every subsequent reboot.

The biggest risk that the script eliminates is silent failures. Without the verification block, a server could complete its initial setup with nginx never having been started, but nobody would realize until the client demonstration.
