The automated job executes the disk_report.sh file, which provides information about disk space for the server using df -h and saves this information into a dated log entry. This automated process replaced the weekly disk space check that was previously performed manually by the team lead. A copy of all previous disk reports will be stored because each time the automatic disk report runs, it appends to the disk_report.log file located in the logs directory under my user name. If there is an error while running the disk report during its scheduled run, it will be logged to disk_report_cron.log via redirection of standard error to standard out.

The disk report has been set up to run automatically at 6:00 AM Sunday, per the server's clock. Since the server is configured for UTC, this equates to 1:00 AM CDT. Prior to establishing the above scheduling, I tested the job on a frequent schedule. The test was conducted by executing the script every two minutes. The disk report log file indicated activity at 00:26:01 and 00:28:01. Syslog confirmed both executions had been made by cron at those times. No entries were found in the cron output log file indicating either execution resulted in an error.

Automating this task ensures that any issues related to storage are documented every week regardless of whether anyone is aware that they should review their systems. An added benefit of documenting these tasks is the ability to provide a record of when each report was executed and what findings were contained within each report.
