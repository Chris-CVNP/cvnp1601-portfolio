# Provisioning Summary

I made the devuser account using useradd -m -s /bin/bash, which assigned the new account a UID of 1001, a GID of 1001, a default home directory of /home/devuser and a login shell of /bin/bash. The home directory was created and owned by the devuser account. Therefore I wasn't able to access into this account's home directory without being root using sudo. I also created the developers group, which has a GID of 1002, and added the devuser account to the developers group using the usermod -aG option to avoid dropping any other group memberships the devuser account may have been a member of. To confirm whether or not the devuser account was now a member of the developers group, I compared the output of id devuser before and after making the change.

Using visudo to edit the sudoers file, I added the following line to permit the restart of the nginx service: devuser ALL=(ALL) NOPASSWD: /usr/bin/systemctl restart nginx. I used /usr/bin/systemctl because that is the path the system returned when I ran which systemctl, rather than the /bin/systemctl shown in the guide. After running visudo to add the above line to the sudoers file, I switched to the devuser account with sudo -u devuser bash and entered sudo /usr/bin/systemctl restart nginx. The restart command successfully executed, there was no password prompt for authentication, and there were no errors displayed. Then I ran systemctl status nginx, which confirmed that the nginx service had actually restarted. As expected, entering sudo /usr/bin/systemctl stop nginx prompted me to enter a password for sudo authentication first; however, once I did so, the stop command failed to execute due to sudo refusing to allow a match on the granted rule.

Entering sudo -l as the devuser account produced exactly one permitted command and nothing else, which demonstrates that the permission rule that was granted was specific enough to match against the ticket issued to the devuser account. Finally, as part of completing the optional clean-up process, I removed the sudoers rule for restarting nginx using visudo, then deleted the devuser account with userdel -r, followed by deleting the developers and testgroup groups.
